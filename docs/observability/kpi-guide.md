# KPI Guide

## Lead time
Task start to completion.

## Retry count
How often nodes repeat without structural replanning.

## Replan count
How often new evidence changed the workflow.

## Unexpected impact
How often actual graph impact exceeded predicted impact.

## Self-correction count
How often feedback caused a successful DAG modification.

## PR gate failure
How often work reached the final gate but still failed verification.

These KPIs are useful for improving Harness quality, not ranking individual developers.
